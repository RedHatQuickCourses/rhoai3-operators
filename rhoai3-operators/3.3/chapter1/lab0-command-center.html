Lab: Assembling the AI Engine Room

Clickops does not scale. It is time to apply configuration as code.

In this lab, you are a platform engineer tasked with bootstrapping a greenfield OpenShift cluster into a Models-as-a-Service (MaaS) factory. While you could install these operators one by one through the OpenShift Web Console UI, real factories are built with automation and code.

To execute this, we will first install the Red Hat Web Terminal Operator via the UI. This provides a secure, in-cluster command-line interface directly within your browser. From there, we will deploy the rest of the MaaS operator stack using the oc CLI.

[IMPORTANT] .Prerequisites Access to an OpenShift cluster with cluster-admin privileges.

Worker nodes equipped with target hardware accelerators (e.g., GPUs).

== Step 1: Gain CLI Access (The Web Terminal)

Before we can run our deployment scripts, we need a terminal connected to the cluster.

Log in to the OpenShift Web Console as a cluster administrator.

Navigate to Operators → OperatorHub (or Ecosystem).

Search for Web Terminal and click the Red Hat Web Terminal card.

Click Install and accept the default settings.

Wait for the installation to succeed.

Launch the Terminal: Look at the top right of the OpenShift Web Console header. You will now see a command-line icon (>_). Click it.

A terminal window will initialize at the bottom of your screen, pre-authenticated with your admin credentials.

== Step 2: Lay the Hardware Foundation (NFD & GPU)

Now that you are in the terminal, we will use Kubernetes manifests (YAML) to instruct the Operator Lifecycle Manager (OLM) to subscribe to our required infrastructure operators.

  1. Create the NFD Namespace & Subscription: + [source,bash] cat <<EOF | oc apply -f - apiVersion: v1 kind: Namespace metadata: name: openshift-nfd apiVersion: operators.coreos.com/v1alpha1 kind: Subscription metadata: name: nfd namespace: openshift-nfd spec: channel: stable installPlanApproval: Automatic name: nfd source: redhat-operators sourceNamespace: openshift-marketplace EOF

  2. Activate NFD (Create the Custom Resource): Wait a minute for the operator pod to start, then tell NFD to scan your nodes. + [source,bash] cat <<EOF | oc apply -f - apiVersion: nfd.openshift.io/v1 kind: NodeFeatureDiscovery metadata: name: nfd-instance namespace: openshift-nfd spec: operand: image: registry.redhat.io/openshift4/ose-node-feature-discovery:v4.14 topologyupdater: false EOF

  3. Deploy the NVIDIA GPU Operator: With NFD labeling your nodes, deploy the GPU operator to inject the drivers. + [source,bash] cat <<EOF | oc apply -f - apiVersion: v1 kind: Namespace metadata: name: nvidia-gpu-operator apiVersion: operators.coreos.com/v1alpha1 kind: Subscription metadata: name: gpu-operator-certified namespace: nvidia-gpu-operator spec: channel: v23.9 installPlanApproval: Automatic name: gpu-operator-certified source: certified-operators sourceNamespace: openshift-marketplace EOF (Note: After this subscription installs, a ClusterPolicy CR must be created. In many OpenShift environments, the operator can auto-generate a default policy once it detects GPU labels).

== Step 3: Deploy the Networking & Distributed Serving Layer

To serve models securely and across multiple nodes, we need our certificates and distributed workload managers.

 [source,bash]
. Install cert-manager:
cat <<EOF | oc apply -f - apiVersion: operators.coreos.com/v1alpha1 kind: Subscription metadata: name: openshift-cert-manager-operator namespace: cert-manager-operator spec: channel: stable-v1 installPlanApproval: Automatic name: openshift-cert-manager-operator source: redhat-operators sourceNamespace: openshift-marketplace EOF
. Install LeaderWorkerSet (LWS): (Required for llm-d distributed runtime). + [source,bash]
cat <<EOF | oc apply -f - apiVersion: operators.coreos.com/v1alpha1 kind: Subscription metadata: name: leader-worker-set namespace: openshift-operators spec: channel: alpha installPlanApproval: Automatic name: leader-worker-set source: redhat-operators sourceNamespace: openshift-marketplace EOF
== Step 4: Install the Meta-Orchestrator (OpenShift AI)

Finally, with the infrastructure, networking, and serving operators in place, we deploy the "brain" of the operation: the Red Hat OpenShift AI Operator.

  1. Deploy the RHOAI Operator: + [source,bash] cat <<EOF | oc apply -f - apiVersion: operators.coreos.com/v1alpha1 kind: Subscription metadata: name: rhods-operator namespace: redhat-ods-operator spec: channel: fast installPlanApproval: Automatic name: rhods-operator source: redhat-operators sourceNamespace: openshift-marketplace EOF

  2. Verify the Fleet: Run the following command to ensure all your operator subscriptions have successfully registered and are updating. + [source,bash] oc get csv -A | grep -E 'nfd|gpu|cert-manager|rhods|leader' Expected Output: You should see a list of Cluster Service Versions (CSVs) showing Succeeded in the final column.
