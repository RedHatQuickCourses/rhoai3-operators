Lab 0 — Establishing the command center

Before you build the factory, you need a control room. Leave the brittle laptop toolchain behind.

Reproducible MaaS and GitOps demand a consistent shell. The OpenShift Web Terminal Operator gives every authorized admin an authenticated oc session inside the console—no VPN-split routing debates for basic tasks.

The bootstrapping paradox

To run declarative commands, you need a client. Two paths:

  • Method 1 (UI) — fastest when you have admin console access only.

  • Method 2 (CLI/GitOps) — when you already have oc and want subscriptions in Git.

Method 1 — UI bootstrap (recommended)

Step 1 — Install

  1. Log in to the OpenShift console as cluster admin.

  2. Open Ecosystem → Software Catalog (or Operators → OperatorHub, depending on console version).

  3. Search for terminal.

  4. Install Web Terminal (Red Hat). Approve the InstallPlan if your cluster uses manual approval.

Method 2 — CLI alternative (GitOps)

Step 1 — Subscription

cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: web-terminal
  namespace: openshift-operators
spec:
  channel: fast
  name: web-terminal
  source: redhat-operators
  sourceNamespace: openshift-marketplace
EOF

Step 2 — Verify CSV

oc get csv -n openshift-operators | grep web-terminal

Expect Succeeded.

Initialization

  1. Click the terminal icon (>_) in the console header.

  2. Start a workspace (for example project openshift-terminal).

  3. Run:

oc project

You should see the active namespace—proof the session is authenticated.
