Capabilities & features — what the ecosystem gives you

This page is the menu, not the meal. You are choosing control-plane services that make the execution plane (GPUs, serving pods, gateways) predictable, shared, and measurable.

The table below is the platform engineer’s feature list: what each layer does for ROI (shared capacity, shorter TTFT, fewer outages) without naming every CRD.

Layer What you get Factory outcome

OLM / Catalog sources

Subscriptions, channels, install plans, CSV health, dependency edges between operators

Repeatable installs, audited upgrades, fewer "works on my laptop" clusters

Red Hat OpenShift AI operator (meta-operator)

Watches DataScienceCluster; reconciles dashboard, registry, serving stacks, and optional components per policy

One declarative object (DSC) expresses intent instead of twenty Helm charts

DataScienceCluster (DSC)

Per-component managementState (Managed, Removed, …) for dashboard, model registry, KServe, Ray, Codebases, legacy ModelMesh, etc.

You pay RAM/CPU only for the factory you are actually running—critical for multi-tenant cost allocation

Node Feature Discovery (NFD)

Publishes hardware labels (CPU flags, PCI devices, accelerators) on nodes

GPU operators and schedulers see the same truth; placement and profiles stop being guesswork

GPU vendor operators

Drivers, device plugins, MIG/MxGPU-style partitioning where supported

Higher utilization per dollar—shared slices instead of one model per card

Kueue (Red Hat build)

Quotas, priorities, preemption policies for batch and serving workloads

Stops queue sprawl; aligns spend with business priority, not loudest team

cert-manager (OpenShift operator)

Issuers, certificates, renewals for in-cluster TLS consumers (e.g., serving stacks)

Eliminates manual cert rotation theater before inference goes live

Connectivity Link + Gateway API path

Kuadrant-style policy attachment, authN/Z hooks, rate limits on ingress to models

Turns raw endpoints into products with SLAs—internal MaaS without anonymous GPU burn

Leader Worker Set

Orchestration primitive for leader/worker distributed pods (used by distributed inference patterns)

Lets very large models span devices/nodes instead of forcing vertical-only designs

Technology Preview truth: MaaS, some gateway integrations, and preview operators change fastest. Before you promise the business a capability, match the Release notes and Installing OpenShift AI guide for your exact 3.3 build.
