Lab 2 — Deploying governance dependencies

An unmanaged endpoint is a liability. A governed endpoint is a product.

Lab 1 gave you the meta-operator and hardware truth. Before inference traffic should flow, install the TLS factory and the policy plane the journey expects for Phase 2–3.

1. cert-manager (OpenShift operator)

KServe-oriented stacks commonly depend on in-cluster certificate issuance—avoid one-off TLS secrets.

cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: openshift-cert-manager-operator
  namespace: cert-manager-operator
spec:
  channel: stable-v1
  name: openshift-cert-manager-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
EOF

ROI link: No cert-manager → serving reconciliation stalls or runs insecure-by-exception—both are expensive conversations with security teams.

2. Red Hat Connectivity Link

Installs the Kuadrant-oriented connectivity layer used with Gateway API patterns for governed MaaS exposure (confirm feature maturity in release notes).

cat <<EOF | oc apply -f -
apiVersion: operators.coreos.com/v1alpha1
kind: Subscription
metadata:
  name: connectivity-link-operator
  namespace: openshift-operators
spec:
  channel: stable-v1
  name: connectivity-link-operator
  source: redhat-operators
  sourceNamespace: openshift-marketplace
EOF

3. Verification

oc get csv -n cert-manager-operator | grep cert-manager
oc get csv -n openshift-operators | grep connectivity-link

Expect Succeeded for both.
